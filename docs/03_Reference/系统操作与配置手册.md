## 一、 用户快速指引与产品说明 (User Quick Guide & Product Overview)

Lumi 2.0 是一款基于宏观基本面驱动的全球资产配置决策支持系统（即投资副驾驶）。它通过科学的数据量化与客观的执行纪律，帮助投资者排除主观情绪干扰，生成抗波动的季度大类资产推荐比例。

### 1.1 产品核心实现方式
系统采用**“数据管线 + 双引擎决策”**的闭环架构：
- **自动化数据管线**：支持 FRED API 实时数据自动拉取与半自动化快照生成，覆盖增长、通胀、流动性等 8 个核心宏观维度。
- **双引擎决策底座**：
  1. **评分引擎（P1 主线）**：对 18 类资产进行 Z-Score 宏观偏离打分，并生成 P1-LiveFull 实操推荐。
  2. **配置引擎（BL 校验）**：融合 Black-Litterman 贝叶斯最优化，对评分和全球市值均衡权重进行资产相关性约束，防范相关性集中风险。

### 1.2 v2.0 最新功能与核心亮点
- **D3 宏观多步预测**：引入 D3 预测管线，自动基于宏观惯性预测下季度走向，提供可信因子的方向指引。
- **换手稳定器 (防抖)**：内置防抖平滑机制，大幅降低高频变动带来的实操调仓换手摩擦成本，最大程度平滑实盘税费与交易损耗。
- **“增长候选”特化模式**：提供默认稳健模式（长周期夏普比率高达 0.682）以及全新的 Concentrated Capped（集中上限）高收益模式，满足不同资金属性的多档配置需求。
- **5年滚动窗口鲁棒性验证**：已成功通过 2021~2025 年多变宏观窗口的压力测试，录得 10.04% 的稳健回报，印证了系统长效适应力。
- **UI 控制流大合并 (Template Module Consolidation)**：合并冗余模板代码，统一标准交互入口，彻底消除渲染冲突，大幅增强前端图表、回测和诊断界面的运行稳定性与鲁棒性。

# Lumi 双引擎原理与使用指南

**版本**: v2.0  
**最后更新**: 2026-05-31  
**定位**: 解释 P1 与 BL 双引擎的本质区别、使用方法、最新验证逻辑与系统演进成果

---

## 一、核心概念：两套引擎在做什么

### P1 引擎（原版·分层降维评分系统）

**一句话**: 把 10+ 个宏观参数逐层打分，算出每类资产的"吸引力排名"，再按风险分层分配仓位。

**核心逻辑**:
1. 输入当前宏观参数（VIX、利率、通胀等）
2. 对每个资产类别（共17个）打分 → `smartScores`（0~200 分）
3. 按 All Weather 风险分层分配：
   - 低 VIX 时："风险"池占 55%，"避险"池 20%
   - 高 VIX 时：自动缩减"风险"池，增加"避险"池
4. 在各池内按评分比例分配权重

**P1 的盲区**: **完全不考虑资产之间的联动**。它只会说"美股 120 分、债券 80 分"，但不会考虑"美股和发达市场 90% 正相关，同时买太多等于没分散"。

---

### BL 引擎（Black-Litterman·相关性约束验证引擎）

**一句话**: 站在"全球资本市场均衡配置"的起点上，用 P1 的评分作为"观点偏好"，通过协方差矩阵（资产联动关系）做贝叶斯修正，得出一套考虑了相关性的权重。

**核心逻辑**:
1. **起点 = 全球市值均衡**：假设在没有任何观点时，按全球资产市值比持有（美股 35%、欧日 15%、美债 15%、黄金 4% ...）
2. **观点 = 来自 P1 的评分**：把 P1 的 smartScores 转换为"BL 观点"
   - 评分 > 50 → 看多该资产，偏离越大信心越强
   - 评分 < 50 → 看空该资产
3. **约束 = 协方差矩阵**：用 60 个月的 ETF 真实回报率计算资产间联动
   - 高相关资产不会同时获得高权重
   - VIX 高时协方差自动放大（危机期所有资产相关性趋同）
4. **融合**：BL 后验公式 =「均衡先验 + 评分观点 × 信心度 × 协方差约束」
5. **保守混合**：最终 BL 权重 = 60% 优化结果 + 40% 均衡基准（防止极端偏移）

## 二、界面上的四个东西分别是什么

| 界面元素 | 实际含义 | 通俗比喻 |
|---------|---------|---------|
| **P1 权重**（右列） | 原版引擎的单资产评分 → 分层分配结果 | "每科考试分数" |
| **BL 权重**（左列） | 考虑了资产之间相关性的贝叶斯修正权重 | "综合排名（扣掉了重复学分）" |
| **🧮 参考BL权重重新选择资产** | 按 BL 权重 ≥2% 的大类重新勾选资产，然后让 P1 重新计算 | "老师帮你选课，但分数还是你自己考的" |
| **📥 导入协方差** | 更新 BL 引擎底层的"资产联动关系数据" | "更新考试大纲" |

### 「参考BL权重重新选择资产」到底干了什么？

代码逻辑（`ui_v16.js` L2713-2751）：
1. 读取 BL 的推荐权重
2. 筛出 BL 权重 ≥ 2% 的所有资产大类
3. 自动勾选这些大类（清空原有选择）
4. **触发 P1 重新计算**（不是直接用 BL 的权重！）

**所以这个按钮的本质是**：让 BL 帮你做**"选什么"**的决策，但**"怎么分"**还是 P1 说了算。

## 三、什么时候用哪个

| 场景 | 推荐做法 | 理由 |
|------|---------|------|
| **日常查看** | 看 P1 权重为主，BL 为参考 | P1 是经过 43 场景回测验证的核心引擎 |
| **配置偏集中时** | 着重对比 BL 和 P1 的差异 | 如果 BL 大幅偏离 P1，说明你的组合可能有相关性集中风险 |
| **市场剧烈波动时** | BL 的 VIX 动态缩放会自动生效 | 危机期资产相关性趋 1，BL 会自动收缩到更分散的配置 |
| **不确定选什么资产时** | 点「参考BL重新选择」 | 让 BL 帮你决定大方向，P1 负责精细配比 |
| **每半年** | 运行脚本更新协方差 JSON 并导入 | 保持联动关系数据的时效性 |

## 四、怎么验证它们不是"胡说八道"

### 验证 P1：历史回测（已完成）

这就是我们之前做的 **43 个历史场景盲测**：
- 从 1987 到 2025，每个场景输入当时的真实宏观参数
- P1 给出推荐资产和权重
- 与该时段各资产的**实际涨跌**对比
- **结果:  50% 完全匹配 + 53% 部分匹配 + 0% 完全反向**

> 这证明 P1 在一半的历史场景中能准确预测资产走势方向，且从未给出完全错误的建议。

### 验证 BL：需要做的事

BL 的验证逻辑不同于 P1。BL 不是在预测"哪个涨"，而是在回答**"考虑相关性后，你的组合是否足够分散"**。

**验证方法 1：相关性合理性检验**
在浏览器 F12 控制台查看 BL 诊断输出：
```
[BL Engine] 观点数量: 10
  cnStock: 评分=113 → 观点=+12.6% | 信心=26%
  usStock: 评分=109 → 观点=+11.8% | 信心=22%
  precious: 评分=214 → 观点=+32.8% | 信心=100%
```
- ✅ 评分越高的资产，观点収益应越大 → 逻辑正确
- ✅ 评分越极端（离50越远），信心越高 → 逻辑正确
- ✅ 最终 BL 权重不是简单的"评分排序"，而是被相关性修正过 → 这就是 BL 的价值

**验证方法 2：与 P1 的差异分析**
从您截图中可以看到：
| 资产 | BL 权重 | P1 权重 | 差异 | 解读 |
|------|--------|--------|------|------|
| precious | 28.4% | 2.4% | +26% | BL 大幅增配黄金：因为黄金与其他资产低相关，是真正的分散 |
| usStock | 25.7% | 9.5% | -15.9% | 正常，美股评分高但与发达市场高度相关 |
| cnStock | 2.3% | 10.1% | -7.8% | BL 降低了中国股票：可能因与新兴市场的相关性 |

这些差异**不是错误**，而是 BL 在说："P1 给中国股票打了高分，但中国股票和新兴市场高度相关，同时买太多就是伪分散。而黄金跟所有人低相关，是真分散。"

**验证方法 3：BL 诊断面板（已内置）**
展开 UI 的「BL 诊断详情」，可以看到完整的三步推导过程：
- **均衡权重** → 起点
- **隐含收益** → 协方差矩阵 × 均衡权重 = 市场隐含的收益预期
- **BL 后验收益** → 融合观点后的修正收益
- **最终权重** → 按修正收益优化后的配比

如果某一步的数字不合理（如隐含收益全为负），说明协方差数据有问题。

## 五、到底该信 P1 还是 BL？

**答案：都信，但各信不同的部分。**

| 能力维度 | P1 擅长 | BL 擅长 |
|---------|---------|---------|
| 判断"什么资产好" | ✅ 多层宏观因子精细评分 | ❌ 不判断，只修正 |
| 防止"伪分散" | ❌ 完全不考虑相关性 | ✅ 通过协方差矩阵约束 |
| 危机检测 | ✅ VIX 分层联动 | ✅ VIX 动态缩放协方差 |
| 验证难度 | ✅ 可回测（已验证） | ⚠️ 需要长期跟踪验证 |

**推荐用法**：
1. **以 P1 为主线**（它是经过 43 场历史考试的）
2. **以 BL 为校验线**（检查 P1 输出是否有"相关性陷阱"）
3. 当两者差异巨大时，**重点看差异本身**——这往往指向你需要注意的风险

## 一、什么是协方差矩阵？需要多久更新一次？

协方差矩阵描述**各资产类别之间的联动程度和波动率**。  
系统默认使用预设静态值（基于2019-2024学术数据），即使不更新也能正常运行。

**建议更新频率**：每半年 ~ 每年一次。当发生以下情况时可考虑更新：
- 市场结构发生重大变化（如美联储大幅加息/降息周期）
- 资产相关性明显改变（如数字货币与风险资产相关性提高）
- 你想使用最近5年的真实市场数据

## 二、使用脚本自动生成（⭐ 推荐）

系统已内置自动化脚本，可直接从 Yahoo Finance 拉取真实市场数据：

```bash
py scripts/generate_bl_covariance.py --months 60
```

脚本会自动：
1. 拉取 10 个 BL 大类资产的 ETF 月度收益率（SPY, MCHI, EFA, EEM, TLT, CBON, AGG, GLD, GSG, BTC-USD）
2. 对齐所有资产的共同时间窗口
3. 生成符合系统要求的 JSON 文件到 `data/bl_covariance_YYYY-MM.json`

**依赖**: `pip install yfinance`  
**更新频率**: 每半年一次（推荐 1 月和 7 月）  
**详细说明**: 见 [Data_Pipeline_Guide.md](../02_Manuals/Data_Pipeline_Guide.md#脚本-5generate_bl_covariancepy--bl-协方差数据生成-)

## 六、常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 「月度数据不足」 | 某资产不足36个月 | 确保每个资产至少有36个数字 |
| 「JSON 格式错误」 | 缺少 `assets` 字段 | 检查模板完整性 |
| BL 面板仍显示「预设默认值」 | 导入未触发重新计算 | 手动点击「一键AI推荐」 |
| 某资产 BL 权重异常 | AI 提供的收益率单位有误 | 确认用小数（不是百分数） |
