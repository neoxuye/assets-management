## 一、系统概览

Lumi 是一个基于宏观因子的全球资产配置系统，覆盖 18 类资产，通过评分引擎生成季度配置建议。

### 核心性能（25年长周期回测 2000-Q1 ~ 2025-Q4）

| 指标 | P1 纯引擎 | P1-LiveFull（实操基准） | 60/40 基准 |
|------|-----------|----------------------|-----------|
| CAGR | 14.71% | 12.96% | 10.21% |
| Sharpe | 0.682 | 0.626 | 0.509 |
| 超额收益 | +4.5pp | +2.75pp | — |

> 💡 **近五年滚动窗口验证 (2021 ~ 2025)**: 系统已通过滚动窗口压力测试，在近年来高波动市场环境中录得平均 **10.04%** 的年化回报，证实了评分机制与稳定器极强的鲁棒性与无过拟合特征。

### 关键路径说明

```
P1（纯打分）     → 理论上限，用于评估引擎质量
P1-LiveFull      → 实际使用的推荐路径（含风险偏好约束 + 换手稳定器）
P1+BL            → 实验性功能，作为相关性集中风控校验参考
```

**你日常只需关注 P1-LiveFull 的推荐结果。**

## 二、季度运营流程

### 时间节点

每季度初（1月/4月/7月/10月的第一周）执行以下步骤：

### Step 1: 更新宏观数据（5分钟）

```powershell
cd "D:\work\xuye\finance\Assets balance\lumi_v2.0"

# 自动从 FRED 拉取最新宏观数据，追加到 quarterly_snapshots.json
py -3 scripts/update_snapshots.py
```

**预期输出**：
```
保留模式: 仅追加新季度（已有数据不变）
当前 snapshots: 104 季度 (2000-Q1 ~ 2025-Q4)
从 FRED 拉取宏观数据...
  ✅ inflation: 106 季度
  ✅ yieldCurve: 107 季度
  ...
完成: 更新 0 个值, 新增 1 个季度
```

> **注意**：FRED 能自动拉取的因子：inflation, yieldCurve, globalGrowth, fedRate, realYield, usd, vix, creditSpread。
> 
> 以下因子需要**手动补充**（编辑 `data/quarterly_snapshots.json` 对应季度）：
> - `rateChangeReason`, `usdReason`, `vixReason`, `inflationReason`（定性判断值 -1~1）
> - `cnPolicy`（中国政策方向）
> - `momentum`（市场动量判断）
> - `sofrOisSpread`, `pmiDelta`, `fedDotsGap`（领先指标）

### Step 2: 生成预测（2分钟）

```powershell
py -3 scripts/d3_macro_predictor.py
```

**预期输出**：看"下季度预测"部分，关注：
- **方向**（↑/↓）是否符合你的判断
- **置信度**（high/medium/low）
- globalGrowth 目前命中率低（36.8%），其预测仅供参考

### Step 3: 打开系统查看推荐（5分钟）

1. 用浏览器打开 `index.html`
2. 在左侧面板确认宏观参数已更新（应显示最新季度值）
3. 点击**「一键 AI 推荐」**
4. 查看推荐配置比例

### Step 4: 记录决策（3分钟）

在 `data/decision_log.json` 中记录：
```json
{
  "2026-Q2": {
    "date": "2026-04-28",
    "systemRecommendation": { "usStock": 0.18, "bonds": 0.22, ... },
    "actualDecision": { "usStock": 0.15, "bonds": 0.25, ... },
    "deviationReason": "个人判断美股短期偏高，增配债券",
    "macroContext": "Fed暂停加息，VIX=15"
  }
}
```

### Step 5:（可选）跑回测验证

如果你修改了宏观参数或想验证系统稳定性：
1. 打开 Walk-Forward 面板
2. 运行完整回测
3. 确认 P1-LiveFull Sharpe ≥ 0.60

## 三、如何看懂系统输出

### 3.1 推荐页面

| 区域 | 含义 |
|------|------|
| 资产评分表 | 每个资产的综合得分（0-100），50=中性 |
| 推荐权重 | P1-LiveFull 链路输出的最终配置比例 |
| 宏观仪表盘 | 当前 8 个宏观因子的值和历史分位 |
| D3 预测面板 | 下季度各因子预测方向和置信度 |
| **BL 诊断详情** | **[核心诊断]** 展现从“均衡起点 → 隐含收益 → 后验收益 → 最终权重”的贝叶斯修正全链条，辅助排除资产相关性集中风险 |

### 3.2 Walk-Forward 报告

| 策略 | 用途 |
|------|------|
| P1 纯打分 | 引擎理论上限，Sharpe ≥ 0.65 说明引擎健康 |
| P1-Smooth | P1 + 换手平滑，介于 P1 和 LiveFull 之间 |
| P1-LiveFull | **实操基准**，引入风险上限与稳定器，Sharpe ≥ 0.60 说明系统可用 |
| P1+BL | **风控校验线**，用来验证 P1 资产池是否存在伪分散和高相关性集中风险 |
| 等权/60-40 | 基准对比，系统应持续跑赢 |

### 3.3 预测报告（d3_macro_predictions.json）

| 字段 | 含义 |
|------|------|
| `direction_accuracy` | 历史方向命中率，≥55% 可信，<50% 仅参考 |
| `confidence` | high（命中率≥60%）/ medium（≥50%）/ low（<50%） |
| `delta` | 预测变化量，正=上升，负=下降 |

**可信因子**（命中率≥55%）：fedRate(68%), inflation(60%), yieldCurve(60%), creditSpread(57%), realYield(56%)

**参考因子**（命中率<55%）：usd(55%), vix(52%), globalGrowth(37%❌)

## 五、系统更新节奏

### 常规运营（每季度）
- 跑 `update_snapshots.py` + `d3_macro_predictor.py`
- 看推荐，做决策，记录 decision_log

### 系统评估（每半年 / 2个季度后）
- 跑完整 Walk-Forward 回测
- 对比 P1-LiveFull Sharpe 是否仍 ≥ 0.60
- 检查 decision_log 中系统推荐 vs 实际收益的差异
- 如果 Sharpe 显著下降（<0.55），考虑调参或排查

### 系统升级触发条件
| 信号 | 行动 |
|------|------|
| P1-LiveFull Sharpe < 0.55 连续 2 季度 | 审查评分因子权重 |
| 某因子命中率从 >55% 降到 <45% | 检查该因子数据源是否变化 |
| 新增可用数据源（如 PMI 实时数据） | 评估是否接入 |
| 市场结构性变化（如新资产类别兴起） | 评估是否扩展资产库 |

### 极端市场人工介入
当市场发生 system 无法提前预测的冲击时，先暂停执行系统推荐，改用人工防御流程。

触发条件（任一满足即可）：
- VIX > 40 且 creditSpread > 3.0
- 标普500单日跌幅 > 5%
- 主要交易所、银行、主权信用或地缘冲突出现重大突发事件

处理方式：
- 不使用当日自动推荐作为调仓依据
- 临时目标组合参考：美债 40% + 贵金属 25% + 现金 35%
- 在 `data/decision_log.json` 记录触发原因、实际操作和恢复条件
- 等 VIX 回落到 30 以下，且 creditSpread 连续 2 周不再走阔后，再恢复季度 SOP

### 不建议频繁做的事
- ❌ 每次回测后调参数——容易过拟合
- ❌ 根据单季度表现判断系统好坏——至少看 4 季度
- ❌ 手动 override 太多因子——系统的价值在于纪律

### 默认模式与增长候选

默认实操仍使用稳健模式：

| 参数 | 设置 |
|------|------|
| 稳定器 | 稳健 0.18/0.38 |
| Allocation Style | Risk Parity |
| Risk Preference | Balanced |

增长候选只作为可选高风险模式，不替换默认模式。需要使用时，在 Walk-Forward 区点击 `增长候选` 按钮，系统会设置：

| 参数 | 设置 |
|------|------|
| 稳定器 | 稳健 0.18/0.38 |
| Allocation Style | Growth Candidate: Concentrated Capped |
| Risk Preference | Balanced |

使用条件：
- 只能用于回测验证或明确接受高回撤的增长账户。
- 历史最大回撤约 -42%，明显高于默认稳健模式约 -32%。
- Live 换手约 24，高于默认稳健模式约 10，实际交易成本和税务影响需要自行评估。
- 不建议把增长候选用于全部资金；如实盘使用，应限制资金比例，并在 `decision_log` 记录原因。

当前不建议使用 `Experiment: Capped Sticky` 作为正式模式。它降低换手有限，Sharpe 低于 `Concentrated Capped`。

## 七、故障排除

| 问题 | 解决方案 |
|------|---------|
| FRED 拉取失败 | 检查网络；将 `FRED_API_KEY` 设空后手动填数据 |
| Walk-Forward 结果异常 | Ctrl+Shift+Delete 清浏览器缓存后重新打开 |
| 推荐权重全部接近等权 | 检查宏观参数是否为空或全部为默认值 |
| update_snapshots.py 报错 | 确认 `data/quarterly_snapshots.json` 格式正确 |
| 需要恢复旧版本 | 使用 `js/` 下 of `*_backup_*.js` 文件覆盖 |
